# Work unit 060: AIM, the second game

**From:** arcade (stu32-arcade docs/aim.md) · **Ruled by:** Michael's decision 71 (abacus aa30714: the second game,
"Make them all!"), its name AIM ("Aim is fine", abacus #6064) · **Gate:** soroban · **Status:** built and measured on
the host; the board run is the gate's.

## What it is

Four tiles, each a digit 1 to 9, and a target from 10 to 30 that grows with the streak. The player enters the tiles in
RPN on the calculator's own keys, each once, with + − × ÷, exact fractions between (8 ENTER 3 ENTER 8 ENTER 3 ÷ − ÷
is 24). ← undoes a step; the soft keys are UNDO, SKIP and SHOW, which gives the round up and writes one solution as the
keys to press. Every round's target is drawn from the values its tiles reach, so none is unsolvable. The game is
stu32-arcade games/aim at 5fe8cea (aim_logic: the rules, the solver and the generator; aim_app: the app_def), MIT,
written for the STU-32. Nothing calls it "24" (Suntex's marks).

The series is one commit: games.list lists `aim` at 5fe8cea, and device/standin/aim.txt is its board script.

## The checks (stu32-arcade `make aimcheck`, on the host, at 5fe8cea)

1. The C solver against an independent Python enumerator (oracle/aim/reach.py, itself checked against a brute-force
   RPN enumerator), all 495 sets of four digits, targets 1-100 with their solution counts: identical.
2. The rules against an independent Python model (oracle/aim/rules.py): a hand-checked script, 40 fuzzed seeds of 250
   rounds, and every SHOW answer for every set and reachable target (23,793), each of which must win: identical, all
   won.
3. Every round the generator makes for seeds 0-9,999 at each of the five levels (50,000): solvable, in range, and under
   the level's solution cap whenever the tiles allow.
4. The app on the SDK runner: twelve rounds won by their SHOW keys and a script of every refused key, frame hashes as
   committed, 12 tunes and 6 tones, the saves as expected; and the same two scripts through the .wasm and the bridge
   (wamrc from the pinned series), with the same frames and saves.
5. Planted, each red: a solver that never divides, a tile used twice, a generator past its range, a draw without the
   used-tile shade.

## The board (device/standin/aim.txt, for the gate)

APPS lists KEYS, BABAL and AIM; AIM's title, ENTER for a round, FRAMEBENCH, a refused key (0 ENTER: no tile is 0),
then 20 rounds through SHOW and NEW, each running the solver and the generator on the chip. The tiles come from the
hardware RNG, so winning stays the host's check. Then the calc task's stack-free (at least 2,048), C, and 2 ENTER 3 +
must give 5. The gate's first run (soroban, 2026-10-10) sent the rounds back to back and the console dropped keys
in the burst; it now pauses 0.2 s after each NEW, as soroban measured, and reads stack-free before `app:`, which X
prints first.
